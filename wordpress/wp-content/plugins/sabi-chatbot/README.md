# SABI Chatbot

Project-owned WordPress plugin for the SABER College virtual guide.

## Current phase

Version `0.6.1` implements:

- isolated plugin activation and settings;
- an administrator capability named `manage_sabi_chatbot`;
- a simplified WordPress administration panel;
- the `[sabi_chatbot]` shortcode;
- an interactive administrator preview;
- initial SABI content, sources, appearance, API preference and security defaults.
- an accessible launcher and conversation panel with keyboard controls;
- responsive desktop and mobile layouts;
- visual states for ready, typing, loading and connection errors.
- a browser-only simulated conversation with 13 controlled topics;
- English and Spanish interface and responses;
- suggested questions, verified internal links and safe fallbacks;
- special handling for historical programs and sensitive-data prompts.
- a bilingual conversational lead flow for name, program, email, phone and consent;
- server-side validation, nonce protection, a honeypot and rate limiting;
- a dedicated WordPress table that stores leads without conversation transcripts;
- a private lead list with search, protected deletion and CSV export;
- optional email notifications, disabled by default.
- a local institutional knowledge library with 16 approved current sources;
- page-aware extraction of three authoritative PDFs (231 pages total);
- local chunk search with source, page and review-date traceability;
- protected knowledge rebuilding from the WordPress administration panel;
- explicit exclusion of historical documents from the current index;
- source mappings for every controlled conversational topic;
- a custom SABI icon in the WordPress administration menu.
- server-side OpenAI Responses API integration with credentials read from the environment or encrypted WordPress storage;
- retrieval of up to six local institutional fragments before each free-form answer;
- source markers and links that connect model answers with the local knowledge library;
- bounded browser-memory history, provider timeouts, one controlled retry, safe errors and request limits;
- technical usage metrics without storing visitor questions, answers or retrieved source text;
- an offline API contract test for the complete request and response pipeline.

The composer, conversational lead flow and AI responses are active only in the administrator preview while the public shortcode output remains disabled. SABI offers contact only after an explicit signal of interest and requests one field per turn. Conversation messages are processed in browser memory and are not stored. The completed lead is sent only after consent and final confirmation. The OpenAI key is never returned to the browser. It can be supplied by the server environment or encrypted before storage in a dedicated, non-autoloaded WordPress option. AI Engine remains active and unchanged during development.

The integration is implemented and its offline contract test passes. Live OpenAI responses additionally require an active API balance; an account with exhausted credit receives SABI's safe temporary-unavailability message.

## Knowledge maintenance

The bundled PDF index is generated by `tools/build-knowledge-index.py` and stored in `knowledge/index.json`. WordPress imports that versioned bundle and indexes the approved Elementor pages locally. Administrators can review status, test searches, and use **Rebuild knowledge** under **SABI Chatbot > Sources**. Rebuilding never sends documents outside WordPress.

## API configuration

The recommended reproducible setup is `OPENAI_API_KEY` in the project `.env.local` file. Docker injects that value into the WordPress container through the optional `env_file` entry. Alternatively, an administrator can enter a credential under **SABI Chatbot > API**. The plugin encrypts it using the installation's WordPress authentication salt, stores only ciphertext, never repopulates the password field, and gives it priority over the environment value. Removing it restores the environment fallback.

Do not add a plaintext key to source code, documentation, SQL exports or Git. An encrypted credential depends on the current WordPress salts; use `.env.local` when the same credential must work reproducibly on another computer.

Run the non-billable contract test with:

```powershell
docker compose exec -T wordpress wp eval-file wp-content/plugins/sabi-chatbot/tests/api-contract.php --allow-root
```
